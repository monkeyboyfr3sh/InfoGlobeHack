# Olympia Infoglobe IR protocol

Findings from testing the globe with the firmware's Protocol Explorer (web UI → Explorer tab).
Raw observations are kept on the globe (`GET /notes`); this page is the cleaned-up summary.

Status: **all 38 transition effects mapped and confirmed** (2026-11-01). Machine-readable catalogue: [`effects.json`](effects.json).

## Link layer

| Property | Value |
|---|---|
| Carrier | 38.54 kHz, 50 % duty |
| Bit time | 1 ms |
| Bit order | MSB first, bytes back to back, no start/stop bits |
| Encoding | bit `0` = carrier on, bit `1` = LED off |
| Idle | LED off |
| Frame boundary | idle gap after each frame (the receiver uses it to find the next frame); 10 ms is reliable, the minimum is not yet known |
| Max frame | ~40 bytes used so far (2-byte header + up to ~35 text bytes + trailer) |

Generated by the ESP32 RMT peripheral (`main/src/ir_led_task.c`), so bit timing is hardware-exact.

## Character set

From the Character set test (camera capture `PXL_20261102_035511574.mp4`, stills in `captures/`).
The font is a cut-down 7-row ASCII set, apparently made for caller-ID style messages.

| Bytes | Shown | Blank (not in the font) |
|---|---|---|
| `20`–`27` | space `!` `"` `#` `$` `'` | `%` `&` |
| `28`–`2F` | `(` `)` `*` `,` `-` `.` `/` | `+` |
| `30`–`3F` | `0`–`9` `:` `<` `=` `>` `?` | `;` |
| `40`–`5F` | `A`–`Z` | `@` `[` `\` `]` `^` `_` |
| `60`–`7F` | `a`–`z` (true lowercase with descenders) | `` ` `` `{` `\|` `}` `~` `DEL` |
| `80` | **envelope icon** (box with an M-shaped flap) | – |
| `81`–`FF` | – | all |

Practical notes: no `%` or `+` (write `CPU 42`, `42 pct`); `0x80` is a ready-made "message/alert" symbol.
Glyph widths vary (e.g. `#`, `M`, `W` are wide; `!`, `i`, `l` narrow), so text width is not a fixed 8 characters.

## Display geometry and text length

From the Text length test (camera capture `PXL_20261102_040254379.mp4`, effect 0, 1–35 characters).

- **Text is never cut off.** All lengths up to 35 characters (the frame limit) are shown in full and spin around the globe.
- **The band holds about 37–38 character widths** around the whole circumference (at 35 characters the end meets the start with a small gap).
- **Short text is repeated around the band** with a gap of a few characters, like a ticker: 1 character appears many times, 4 characters about twice in view, 8–12 characters repeat with a gap. A short message (e.g. the clock) can be read from any side.
- **Visible front window:** about 12 characters edge to edge, about 8 comfortably readable in the middle.
- Character widths vary (see *Character set*), so these figures are approximate.

## Blink (command `05`)

From the Blink byte test (camera capture `PXL_20261102_041106217.mp4`, text `BLINK nn`).

- The blink byte **n** makes the **first n − 1 characters** of the text blink; the rest stay steady. 0 and 1 mean no blinking; text length + 1 (or more) blinks everything.
- Rate is about **1 Hz** (on ~0.5 s, off ~0.5 s).
- Blinking always covers the **start** of the text, so to blink one word, put it first (e.g. `DOWN NAS`, or the `0x80` envelope icon in front of a message).

## Shift / position (command `05`)

From the Shift byte test (camera capture `PXL_20261102_041458653.mp4`, text `SHIFT nn`).

- `05` frames are **static**: the text does not spin, it stays where the shift byte puts it.
- Each step of the shift byte moves the text **left by about one dot column** (~1/5 of a character). 0 = far right, about 8 = centred in front for 8 characters (the clock's setting), 16 = far left with the first letters off the window.
- So `05` frames are the way to show still, precisely positioned text; effect frames (`00`) always spin.

## Second byte (all frame types)

From the Second byte test (camera capture `PXL_20261102_045819838.mp4`, text `E2 nn`, effect 0).

- The byte after the command is **not a setting**: it is simply the **first character of the text**. `00` draws nothing (that is why every known frame has `00` there); values 1-15 put an extra glyph in front of the text.
- Control codes `01`-`1A` are **accented letters** (camera capture `PXL_20261102_050925740.mp4`, Control characters test):

| Codes | Glyphs |
|---|---|
| `01`-`08` | à á â ä è é ê ë |
| `09`-`10` | ì í î ï ò ó ô ö |
| `11`-`18` | ù ú û ü Ç ñ, then two unclear symbols (`17`, `18`) |
| `19`-`1A` | an i-like glyph (`19`), É (`1A`) |
| `1B`-`1F` | blank |

  So text in French, Spanish or German mostly works: the designer can map these letters to their codes. `00` is the only code that draws nothing, which is why it ends the text.
- Transition and speed did not change. The same holds for `05` frames (camera capture `PXL_20261102_052616164.mp4`): the glyph appears in front of the still text.
- So every frame is really `<command> <text, NUL-padded> ...`; keep byte 2 as `00` unless the first character should be one of the accented letters.

## Frame formats

`[command] [byte 2] [text …] [trailer …]`

| Command | Layout | Meaning |
|---|---|---|
| `00` | `00 00 <text> <effect>` | Show text using transition `<effect>` (see below); spins afterwards |
| `01`, `07` | `01 00 <text> 00` | Still text, left-aligned, appears instantly, no spin |
| `02` | `02 00 <text> 00` | Whole text flashes on/off (~1 Hz); a small underscore shows while off |
| `03`, `04` | `04 00 <text> 00` | Show text immediately and spin it |
| `05` | `05 00 <text> 00 <blink> <shift>` | Still, positioned text; used by the clock. `<blink>` = 1 + number of leading characters that blink (0/1 = none, len+1 = all); `<shift>` = horizontal position |
| `06` | `06 00 <text> 00` | Starts the current still text spinning, then brings the new text in ("toggle scrolling") |
| `01`–`04`, `07` alone | single byte | **Blank the display** (`04` is the clean clear-screen) |
| `08`–`1E` even | – | Ignored (also when sent alone) |
| `09`–`1F` odd, `FF` | – | Show text and spin it (same as `04`) |
| `80`, `81` | – | Glitchy: stray glyphs and blank flashes; avoid |

## Transition effects (command `00`)

**Valid range: 0–37.** Effects 38–127 just blank the display (tested 38–64 and 100, plus 255).
**Bit 7 is ignored:** effects 128, 129 and 140 behave exactly like 0, 1 and 12, so 128–165 mirror 0–37 (confirmed).

Unless noted, after the transition the text spins right → left at normal speed.
